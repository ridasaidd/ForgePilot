# FP-018 — V1 Report Mechanical Regeneration

## Task

Create a rerunnable generator for a V1/current project report from committed checklist evidence and current SQLite admission distribution.

## Goal

Replace reliance on the static `runs/FP-META-025/final-v1-project-report.json` claim with generated output that can be rerun and compared.

FP-018 answers one question:

> Can ForgePilot mechanically regenerate the project report from current committed sources and queryable state?

## Background

FP-META-034 found that `final-v1-project-report.json` was not proven mechanically regenerable. FP-017 then created the first admitted and rejected SQLite evidence records, proving admission-state plumbing for `evidence_records`.

The current checklist has changed after the original FP-META-025 final report, so FP-018 must not silently compare a current report to an obsolete static count without recording the source-state difference.

## Scope

Add:

```text
runs/FP-018/generate-v1-report.py
runs/FP-018/generated-v1-project-report.json
runs/FP-018/generated-v1-project-report.md
runs/FP-018/static-report-comparison.json
runs/FP-018/regeneration-summary.md
```

Update:

```text
docs/forgepilot-progress-checklist.md
```

## Required Method

The generator must read:

- `docs/forgepilot-progress-checklist.md`,
- current SQLite admission distribution where available,
- the old static report for comparison only.

It must produce generated JSON/Markdown artifacts.

## Required Boundary

Generated output is authoritative over manual prose for FP-018 interpretation.

If generated output and written interpretation disagree, generated output wins.

## Required Comparison

The generator must compare the generated current report to:

```text
runs/FP-META-025/final-v1-project-report.json
```

and record whether the counts match or differ.

If they differ, the report must say so plainly and not call the old report mechanically reproduced.

## Safety Requirements

This packet must not mutate SQLite data, alter admission state, execute models, change MCP bridge code, rewrite historical reports, or delete historical artifacts.

## Non-Goals

This packet does not solve evidence-record admission event linkage, backfill historical evidence, regenerate old source state from old commits, implement a production CLI command, or resume bridge refactor work.

## Acceptance Criteria

1. Generator script exists.
2. Generated JSON report exists.
3. Generated Markdown report exists.
4. Static-report comparison artifact exists.
5. Generator reads the current checklist instead of hardcoding 27/4.
6. Generator reads current SQLite admission distribution where available.
7. Rerunning the generator produces stable generated counts for the current working tree.
8. Any mismatch with the FP-META-025 static report is recorded honestly.
9. No manual claim is treated as stronger than generated output.
10. Final git status is clean after evidence is recorded.
