# FP-020 — Canonical Evidence Record Admission Event Surface

## Task

Resolve the live ambiguity between the generic `evidence_admission_events` table and the older dedicated `evidence_record_admission_events` table for evidence-record admission events.

## Goal

Define and implement a canonical query surface so ForgePilot does not silently choose the wrong evidence-record admission event table.

FP-020 answers one question:

> Which event surface is authoritative for evidence-record admission, and what happens when the two event tables disagree?

## Canonical Choice

The canonical evidence-record admission event surface is:

```text
evidence_admission_events
```

when:

```text
target_observation_type = evidence_record
```

Rationale:

- it is the generic admission event log used for event-sourced admission,
- it supports review and invalidation through existing admission-review/invalidation tables,
- FP-019 already added and tested `evidence_record` as a valid target type.

The older table remains present but non-canonical:

```text
evidence_record_admission_events
```

It is treated as a legacy/dedicated surface until a later cleanup packet removes, bridges, or formally deprecates it.

## Scope

Add a canonical query helper that reports one of:

```text
GENERIC_EVENT_CANONICAL
LEGACY_EVENT_ONLY_NOT_CANONICAL
DUAL_TABLE_CONFLICT
NO_EVENT
```

Add tests proving:

- generic event only returns canonical,
- legacy event only is detected as non-canonical,
- conflicting generic and legacy events return explicit conflict,
- no event returns explicit no-event state.

Backfill the two FP-017 records into the canonical generic event surface if the implementation is successful.

## Required Backfill Behavior

If backfill is included, current DB must show:

```text
generic_admission_events_total > 0
```

and specifically FP-017 records must have canonical generic events matching their field-level states:

```text
FP-017-POSITIVE-ADMITTED -> ADMITTED
FP-017-NEGATIVE-REJECTED -> REJECTED
```

## Safety Requirements

This packet must not delete legacy tables, rewrite FP-017 evidence records, mutate historical run artifacts, execute models, change model trust state, or alter MCP bridge code.

## Non-Goals

This packet does not remove `evidence_record_admission_events`, backfill all historical evidence, implement dashboards, or resume the MCP bridge shadow refactor.

## Acceptance Criteria

1. Canonical surface is explicitly selected.
2. Canonical query helper exists.
3. Generic-only event returns `GENERIC_EVENT_CANONICAL`.
4. Legacy-only event returns `LEGACY_EVENT_ONLY_NOT_CANONICAL`.
5. Conflicting generic/dedicated events return `DUAL_TABLE_CONFLICT`.
6. No event returns `NO_EVENT`.
7. FP-017 records are backfilled into canonical generic events or explicitly deferred.
8. If backfilled, current DB shows real `evidence_record` generic events > 0.
9. Full typecheck and tests pass.
10. Final git status is clean after evidence is recorded.
