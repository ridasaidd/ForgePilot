# FP-030 — Canonical Scoped Enablement Decision Implementation Packet

## Task

Implement a canonical scoped enablement decision surface in the MCP bridge.

## Goal

Make the object humans read and the object runtime paths enforce the same object.

FP-030 answers one question:

> Can the bridge expose and consume one canonical scoped decision for FP-027 without reintroducing a bypass or weakening the FP-023 fail-closed worker gate?

## Implementation Boundary

This is a bridge source implementation packet.

Implementation must be performed by an OpenCode executor.

ChatGPT must not directly edit bridge source files for FP-030 except to record packets, prompts, verification artifacts, audits, and admission results.

## Context

FP-028 found cross-surface semantic divergence between general status and guarded preflight.

FP-029 traced the live worker path and found no active direct-worker bypass. Direct worker start currently fails closed through the FP-023 hard gate.

FP-030 must preserve that fail-closed behavior until the canonical decision explicitly allows the exact scoped attempt.

## Required Design

Add one canonical evaluator for scoped enablement decisions.

The evaluator must be pure/read-only. It must not create, mutate, consume, start, stop, contact the runner start endpoint, or alter repository state.

All dependencies must be treated as observations.

If any dependency cannot be read or evaluated, `allowedNow` must be false and the specific failure must appear in `blockingReasons`.

## Mutable/Event-Derived Rules

`approvalConsumedForAttempt` must not be a mutable boolean on the approval artifact.

It must be derived from append-only consumption evidence bound to the exact packet/request/model/run-mode/repo commit/branch/approval id.

An approval artifact may record `consumed: false`, but execution eligibility must be derived from validation and consumption evidence, not by trusting a mutable approval flag alone.

## Failure Semantics

The canonical evaluator must fail closed.

Any exception, missing artifact, unreadable dependency, parse failure, stale artifact, scope mismatch, dirty repo, uncommitted required artifact, expired approval, missing consumption evidence, unset boundary decision, or ambiguous network/secret boundary must produce:

```text
allowedNow: false
```

and a machine-readable reason.

## Canonical Surface Requirement

Add or expose a canonical decision function/module that can be consumed by:

```text
human-facing status tool
preflight/validation path
direct worker-start path
remote-runner start path
```

FP-030 may wire read-only status/preflight paths first, but must not enable direct or remote execution unless every exact-scope gate passes.

## Safety Preservation Requirement

The direct worker-start path must remain fail-closed unless the canonical decision for the exact attempt says allowed.

Do not replace the FP-023 gate with a broad global boolean.

## FP-027 Scope Target

The canonical evaluator must support FP-027 scope:

```text

single worker only

process-tree verification required

```

## Non-Goals

FP-030 does not run FP-027, enable execution, start OpenCode, approve execution, perform extraction, or test the real OpenCode process tree.

## Verification Requirements

Executor must provide tests/proofs for:

1. Missing dependency => allowedNow false with reason.
2. Parse/evaluation error => allowedNow false with reason.
3. Missing or uncommitted required artifact => allowedNow false.
4. File-existence-only contract is insufficient.
5. Recorded but unvalidated approval is insufficient.
6. Validated but unconsumed approval is insufficient if consumption is required for the attempt.
7. Consumed evidence must be append-only and exact-scope.
8. Secret boundary cannot pass by construction.
9. Network boundary cannot pass from runner endpoint configuration alone.
10. Status and preflight consume the same canonical decision object or same serialized decision artifact.
11. Direct worker start remains blocked when canonical decision is false.
12. Build passes.
13. Tests pass.

## Admission Rule

Admit FP-030 only if the implementation proves the canonical decision surface exists, fail-closed behavior is tested, direct worker start remains blocked unless exact-scope canonical decision allows it, and no execution is enabled during the packet.
