# FP-031 — First Executor Use Bootstrap Candidate

## Task

Select the first deliberately boring executor-driven change candidate.

## Goal

Avoid using FP-030 as the first real executor-driven implementation.

FP-031 answers one question:

> What is the smallest useful change that can prove executor-driven work can land safely before implementing canonical scoped enablement?

## Decision

The first executor-driven change should be a documentation-only bridge repository change.

Candidate:

```text
Add docs/executor-bootstrap-canary.md to the bridge repository.
```

## Why this candidate

This candidate is intentionally smaller than FP-030.

It proves executor-driven change mechanics without touching source code, runtime behavior, tool schemas, OAuth/Auth0, worker start, worker stop, runner behavior, or execution policy.

## Candidate Scope

```text
workspace: forgepilot-chatgpt-mcp
branch: feature/oauth-auth0
file allowed: docs/executor-bootstrap-canary.md
files forbidden: src/**, package.json, pnpm-lock.yaml, systemd files, scripts, config, tests unless explicitly scoped later
run mode: DESIGN_ONLY or minimal documentation-only executor mode
model: deepseek-v4-pro-high preferred for first attempt
single executor worker only
no source edits
no behavior changes
no service restart
no FP-024 extraction
no FP-030 implementation
no FP-027 process-tree canary
```

## Expected File Content

The new bridge doc should say only:

```text
This file was created by the first scoped executor bootstrap canary.
It does not change bridge behavior.
It exists to prove executor-driven repository change mechanics under ForgePilot evidence controls.
```

## Acceptance Criteria

A future run may be admitted only if:

1. The executor is started through the approved scoped path, not by direct manual editing.
2. The bridge working tree is clean before start.
3. Exactly one bridge documentation file is added.
4. No source files change.
5. No tool contracts change.
6. Build passes if run; if build is skipped, the reason must be recorded.
7. Bridge working tree is clean after commit/evidence capture.
8. Execution is disabled again afterward.
9. V1-O records the attempt as evidence.
10. Any platform-tool block is recorded separately from bridge behavior.

## Relationship to FP-030

FP-030 remains the canonical scoped enablement implementation packet.

FP-031 is not FP-030 implementation.

FP-031 exists only to decide the first executor-use candidate and avoid making FP-030 the first live executor experiment.
