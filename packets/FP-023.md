# FP-023 — OpenCode Worker Start Safety Gate Fix

## Task

Fix the FP-021 safety-gate failure by preventing `forgepilot_start_opencode_worker` from spawning OpenCode while execution is disabled.

## Goal

Ensure OpenCode worker start enforces the same effective disabled-state policy that status tools report, before any worker id, pid, stdout/stderr log, status file, or process is created.

FP-023 answers one question:

> Does `forgepilot_start_opencode_worker` now refuse before spawn when execution is disabled?

## Triggering Evidence

FP-021 recorded:

```text
SAFETY_GATE_FAILURE_CONFIRMED_BY_SOURCE_INSPECTION
```

Root cause:

```text
startOpenCodeWorker spawned after local checks only and did not enforce execution disable status before process start.
```

## Direct Hotfix Justification

This packet modifies bridge source directly instead of using OpenCode because the OpenCode worker-start path itself is the unsafe path.

This is a safety hotfix, not a shadow extraction.

The executor-driven implementation rule remains in force for future feature/refactor implementation work after this gate is fixed.

## Required Fix

Before worker id allocation or worker artifact creation, `startOpenCodeWorker` must refuse if effective OpenCode execution policy is disabled.

Required rejection reasons include:

```text
EXECUTION_DISABLED_GLOBAL
OPENCODE_EXECUTION_DISABLED
DISABLE_SWITCH_ACTIVE
EXECUTION_NOT_ALLOWED
```

## Required Regression Proof

When execution is disabled, a regression script must prove:

```text
no worker id is allocated
no pid file is created
no status file is created
no start-request file is created
no stdout/stderr logs are created
no OpenCode process is spawned
rejection reason includes disabled-state reasons
```

## Safety Requirements

This packet must not start OpenCode, resume extraction, switch live entrypoints, restart services, or relax execution policy.

## Acceptance Criteria

1. Bridge source enforces disabled-state blocking before spawn.
2. Regression proves no worker artifacts or process are created under disabled state.
3. `pnpm build` passes in the bridge repo.
4. `pnpm test` passes in the bridge repo.
5. Bridge source changes are committed.
6. ForgePilot evidence is recorded through the V1-O canonical path.
7. Extraction remains blocked until the fixed gate is observed through the updated MCP bridge or an explicit operator restart/reload occurs.
