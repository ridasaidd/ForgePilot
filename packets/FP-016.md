# FP-016 — Project Report Capability Detail Integration

## Task

Improve the project summary report so it surfaces incomplete V1 capability details directly.

## Goal

Make `pnpm fp -- project-report` useful as the operator's next-work surface without requiring manual inspection of the checklist table.

FP-016 answers one question:

> Which V1 capabilities remain incomplete, and what evidence/boundary does the checklist currently record for each?

## Scope

Update the existing project report implementation.

The report should include:

- incomplete/non-deferred capability entries,
- deferred capability entries,
- capability evidence references,
- capability boundary text,
- clear `NOT_COMPLETE` V1 completion status while incomplete entries remain.

## Required Boundary

The report remains an index over committed evidence and checklist state.

It must not treat checklist status as proof by itself.

## Safety Requirements

This packet must not create SQLite schema, mutate database records, admit evidence, compare models, score packets, rank models, route work, add MCP tools, change bridge code, or rename historical packets.

## Non-Goals

This packet does not implement dashboard UI, MCP report tool, packet archive automation, admission policy, comparison algorithm, or automatic checklist mutation.

## Acceptance Criteria

1. Project report JSON includes incomplete capability details.
2. Project report JSON includes deferred capability details.
3. Project report text output lists incomplete capability details.
4. Project report text output lists deferred capability details when present.
5. Capability evidence and boundary text are preserved.
6. V1 completion status remains conservative.
7. Tests cover capability detail output.
8. Typecheck and test suite pass.
9. Evidence is recorded under `runs/FP-016/`.
10. Final git status is clean.
