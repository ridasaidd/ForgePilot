# FP-015 — Admission and Comparison Reconstruction Report v1

## Task

Implement a first read-only admission/comparison reconstruction report.

## Goal

Make recorded admission and comparison artifacts inspectable without mutating evidence, creating admission, ranking models, or routing work.

FP-015 answers one question:

> What admission/comparison/audit/verification state can be reconstructed from committed artifacts for a packet?

## Scope

Add a reporting module and CLI command.

Recommended command:

```text
pnpm fp -- reconstruction-report --packet-id <PACKET_ID> --json
pnpm fp -- reconstruction-report --packet-id <PACKET_ID>
```

The report should read repo-local files only.

## Required Output Semantics

The report must include at minimum:

- packet id,
- source artifact paths,
- verification artifact presence,
- audit artifact presence,
- comparison artifact presence,
- admission artifact/state presence where detectable,
- reconstructed state labels,
- unknown/missing states when absent,
- required reconstruction boundary text.

## Required Boundary

The report must include:

```text
Reconstruction is read-only. It summarizes recorded state and does not create admission, comparison, ranking, or routing authority.
```

## Safety Requirements

This packet must not create SQLite schema, mutate database records, admit evidence, change comparison outcomes, score packets, rank models, route work, add MCP tools, change bridge code, or rename historical packets.

## Non-Goals

This packet does not implement dashboard UI, MCP tool exposure, archive index, refactor eligibility, global model ranking, routing policy, or admission policy.

## Acceptance Criteria

1. A reconstruction report module exists.
2. CLI supports `reconstruction-report` / `--reconstruction-report` with `--packet-id`.
3. JSON output is supported.
4. Text output is supported.
5. Missing packet fails clearly.
6. Reports verification/audit/comparison/admission state without overclaiming.
7. Unknown/missing state handling is explicit.
8. Report includes required boundary text.
9. Tests cover core reconstruction behavior.
10. Typecheck and test suite pass.
11. Evidence is recorded under `runs/FP-015/`.
12. Final git status is clean.
