# FP-027 — Scoped OpenCode Process-Tree Canary Specification

## Task

Define the first real OpenCode process-tree canary before any extraction retry.

## Goal

Separate execution-safety proof from extraction correctness.

FP-027 answers one question:

> What must be proven by the first scoped OpenCode canary before FP-024 can be retried as a real extraction?

## Current Status

FP-027 is a specification packet only.

It does not enable execution, create a real request, record human approval, start OpenCode, stop OpenCode, or retry FP-024.

## Motivation

FP-026 proved the worker control primitive against a real OS process using a synthetic recorded worker fixture.

That proves the signal mechanism and lifecycle state transition are real, not just bookkeeping.

It does not prove behavior against a real OpenCode process tree.

FP-027 exists to close that gap without mixing it with extraction correctness.

## Required Canary Scope

The first canary must be:

```text
packet-scoped: FP-027
workspace-scoped: forgepilot-chatgpt-mcp
model-scoped: deepseek-v4-pro-high
run-mode-scoped: DESIGN_ONLY
single-worker only
no source edits
no extraction
no bridge refactor
no service restart during the run
short time-boxed window
fresh human approval required for this packet only
```

FP-027 must not inherit FP-024 authorization. FP-024 is an extraction packet. FP-027 is an execution-safety canary.

## Canary Prompt Requirement

The canary prompt must ask for a boring design-only response that takes enough time for a mid-run control action to be issued.

It must not ask for source edits, tests, refactors, file writes, network access, or secret reads.

A prompt artifact is provided at:

```text
runs/FP-027/prompts/process-tree-canary.md
```

## Process-Tree Verification Requirement

“No orphaned OpenCode child processes remain” must be mechanical, not visual.

Before the worker starts, record a baseline process snapshot.

After the worker starts, record:

```text
worker pid
worker process group id
all processes in that process group
all command lines in that process group
```

After the live control action, verify mechanically:

```text
matching pids in worker process group: 0
matching OpenCode descendant pids for that worker: 0
worker status terminal: ABORTED or clean terminal equivalent
status artifact present
start-request artifact present
stdout artifact present
stderr artifact present
```

If any matching process remains, the canary must not be admitted as a successful execution-safety proof.

## Enablement Preconditions

FP-027 cannot run until a separate scoped-enable mechanism proves:

```text
contractComplete: true
humanApprovalRecorded: true
opencodeBoundarySatisfied: true
secretBoundarySatisfied: true
networkBoundarySatisfied: true
runnerExecutionEnabled: true for the scoped window
opencodeExecutionEnabled: true for the scoped window
global disable cleared or overridden only in the approved scoped way
```

The actual source requirements behind these flags must be inspected before designing the scoped-enable packet.

Approval must not be reused from FP-024 or FP-025.

The approval must bind:

## Acceptance Criteria For A Future FP-027 Run

A future FP-027 run may be admitted only if:

1. Scoped enablement is proven before start.
2. Fresh FP-027 human approval is recorded and consumed.
3. OpenCode worker starts under policy.
4. Pre-start, running, and post-control process-tree snapshots are recorded.
5. A mid-run live control action reaches the bridge.
6. Worker status becomes ABORTED or a clean terminal equivalent.
7. Process-group and descendant checks show zero remaining matching pids.
8. Worker lifecycle artifacts are preserved.
9. Bridge working tree remains clean.
10. Execution is disabled again afterward.

## Non-Goals

FP-027 does not perform extraction, refactor bridge source, evaluate model quality, change tool contracts, or authorize FP-024.
